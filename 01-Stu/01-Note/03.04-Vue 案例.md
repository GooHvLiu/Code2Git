###### 数据传递

首先在App.vue中创建一个数据向子传递和创建一个方法传递给子组件，具体实现如下：

App.vue的源码如下：

```vue
<template>
  <div id="app">
    <div class="todo-page">
      <div class="todo-container">
        <UserHeader :addTodo="addTodo" />
        <UserLists :todos="todos" />
        <UserFooter />
      </div>
    </div>
  </div>
</template>
<script>
import UserHeader from "./components/UserHeader";
import UserFooter from "./components/UserFooter";
import UserLists from "./components/UserLists";
export default {
  name: "App",
  components: { UserHeader, UserFooter, UserLists },
  data() {
    return {
      todos: [
        { id: "001", title: "抽烟", done: true },
        { id: "002", title: "喝酒", done: true },
        { id: "003", title: "烫头", done: true },
        { id: "004", title: "开车", done: false }
      ]
    };
  },
  methods: {
    addTodo(todoObj) {
      if (!todoObj) {
        alert("输入数据不能为空");
        return;
      }
      this.todos.unshift(todoObj);
    }
  }
};
</script>
```

> 1. addTodo方法传递给子组件，用于将创建的待完成事项传递回来
> 2. todos是所有待完成事项的模拟数据数组

UserHeader.vue的源码如下：

```vue
<template>
  <!-- 头部显示 -->
  <div class="todo-header">
    <input
      type="text"
      placeholder="请输入您的任务名称，按回车确认"
      v-model="title"
      @keyup.enter="add"
    />
  </div>
</template>
<script>
import { nanoid } from "nanoid";
export default {
  name: "UserHeader",
  data() {
    return { title: "" };
  },
  methods: {
    //当用户点击enter键之后，进入此方式的执行
    add() {
      if (!this.title.trim()) return;
      //创建数据对象todoObj
      const todoObj = { id: nanoid(), title: this.title, done: false };
      //使用父组件传递过来的方法实现数据的子传父功能
      this.addTodo(todoObj);
      //清空显示框数据
      this.title = "";
    }
  },
  props: ["addTodo"]
};
</script>
```

> add方法实际是用户点击回车触发的添加事件，然后对父组件传递过来的addTodo进行实现

这一层级是应用的入口，所有页面都挂载在这里。系统会根据当前访问的路径，判断是否需要渲染底部的导航组件。这些页面构成了 APP 的主要骨架，用户可以在它们之间通过底部 Tab 快速切换。

| 页面名称 | URL 路径       | 对应组件           | 功能描述                               |
| -------- | -------------- | ------------------ | -------------------------------------- |
| 首页     | `/UserMsite`   | `UserMsite.vue`    | 展示附近的商家列表或推荐内容。         |
| 搜索     | `/UserSearch`  | `UserSearch.vue`   | 提供搜索框，用于查找特定商家或美食。   |
| 订单     | `/UserOrder`   | `UserOrder.vue`    | 展示用户的历史订单和当前进行中的订单。 |
| 个人     | `/UserProfile` | `UserSProfile.vue` | 用户中心，包含头像、余额、设置等。     |

> **逻辑提示**：当路由处于上述任意路径时，`App.vue` 或父级组件中的 `<FooterGuide />` 组件应当被渲染（`v-if="showFooter"`）。

| 页面名称 | URL 路径     | 对应组件        | 功能描述                                                     |
| -------- | ------------ | --------------- | ------------------------------------------------------------ |
| 登陆     | `/UserLogin` | `UserLogin.vue` | 登录/注册流程，不需要底部导航干扰。                          |
| 商家     | `/UserShop`  | `UserShop.vue`  | 关键节点：这是二级路由的父容器。点击首页的商家卡片进入此页面。 |

> 这些页面通常是流程性的（如登录）或者需要沉浸式浏览的（如商家详情），进入后底部导航栏会自动隐藏，不再显示底部导航的页面，属于独立/沉浸页面。

###### 二级路由

当用户进入 /shop 页面后，页面内部通常有一个顶部的 Tab 栏（商品、评价、商家），点击这些 Tab 不会刷新整个页面，而是切换 Shop.vue 内部的 <router-view> 内容。

| 子页面名称 | 完整 URL 路径               | 对应组件              | 备注                             |
| ---------- | --------------------------- | --------------------- | -------------------------------- |
| 商家商品   | `/UserShop/UserShopGoods`   | `UserShopGoods.vue`   | 默认显示的子页面，展示菜单列表。 |
| 商家评价   | `/UserShop/UserShopRatings` | `UserShopRatings.vue` | 展示用户对该商家的打分和评论。   |

> 3. 通常配置重定向：当访问 `/shop` 时，自动重定向到 `/shop/goods`。

##### API 接口

|    名称    |                          定义/解释                           |                      核心作用与理解要点                      |
| :--------: | :----------------------------------------------------------: | :----------------------------------------------------------: |
| API (接口) | Application Programming Interface（应用程序编程接口）。 它是前端（浏览器）与后端（服务器）之间进行数据交换的“桥梁”或“通道”。 | - 本质：一个 URL 地址。 - 作用：前端通过这个地址发送请求（Request），后端接收后返回数据（Response）。 - 比喻：就像餐厅的服务员，你（前端）通过服务员（API）告诉厨房（后端）你要吃什么，服务员再把菜端给你。 |
|  接口文档  | 描述 API 接口具体细节的说明书。 通常包含：请求地址、请求方式（GET/POST）、参数说明、返回数据结构等。 | - 重要性：前后端开发的“契约”。前端照着文档写代码，后端照着文档写逻辑。 - 常见工具：Swagger, YApi, Postman, 甚至 Word/Excel 文档。 |
|   对接口   |  前端开发人员根据“接口文档”，编写代码来调用后端接口的过程。  | - 工作内容：使用 Ajax/Axios 等技术发送网络请求。 - 目的：把页面上的静态数据变成从服务器获取的动态真实数据。 |
|    联调    | 联合调试。 指前端和后端开发完成后，将两部分连接起来进行测试和修正的过程。 | - 场景：前端页面做好了，后端接口也写好了，合在一起看能不能跑通。 - 常见问题：参数传错了、数据格式不对、跨域问题等，需要双方沟通解决。 |
| 前后端分离 | 一种软件开发架构模式。 前端负责页面展示和交互，后端负责业务逻辑和数据存储，两者独立开发、独立部署。 | - 优势：分工明确，效率高；前端可以专注于用户体验，后端专注于性能和安全。 - 现状：目前主流的开发模式（如 Vue + SpringBoot/Node.js）。 |
| Mock 数据  | 模拟数据。 在后端接口还没开发好时，前端自己造一些假数据来模拟接口返回的结果。 | - 目的：不让前端开发等待后端进度。 - 实现：使用 Mock.js 或本地 JSON 文件，拦截请求并返回预设的假数据，保证页面能先跑起来。 |
