# 03.05 前端支持

## 技术支持

### 上传文件

#### 基本概念

本章节主要介绍`Vue2+Element UI`实现文件的上传功能。

#### 技术路线

前端：主要采用`Vue2+Element UI`方式，使用 `el-upload` 组件，将文件封装为 `FormData` 发送。

后端：使用 `multer` 中间件接收二进制流，并生成唯一文件名`（UUID）`防止覆盖。

数据库：使用 `mysql2` 将文件的元数据（原文件名、大小、存储路径/URL）持久化到数据库。

存储分支：

- 分支A（本地存储）：使用 `multer.diskStorage` 将文件写入服务器本地磁盘，并通过的 `express.static` 提供访问;
- 分支B（云端存储）：使用 `multer.memoryStorage` 将文件读入内存，通过`AWS SDK`直传至`Cloudflare R2`;

#### 改造显示

通过布局`点击上传`并创建对应配置，完成测试环境的搭建：

```vue
<template>
  <div class="hello">
    <h3>Uploading Files Tool Page</h3>
    <el-upload
      class="upload-demo"
      action="#"
      :on-preview="handlePreview"
      :on-remove="handleRemove"
      :before-remove="beforeRemove"
      multiple
      :limit="3"
      :on-change="handleChange"
      :on-exceed="handleExceed"
      :file-list="fileList"
      :auto-upload="false"
    >
      <el-button slot="trigger" size="small" type="primary">选取文件</el-button>
      <el-button style="margin-left: 10px" size="small" type="success" @click="submitUpload">上传到服务器</el-button>
      <div slot="tip" class="el-upload__tip">只能上传jpg/png文件，且不超过500kb</div>
    </el-upload>
  </div>
</template>

<script>
import axios from "axios";
export default {
  name: "HelloWorld",
  data() {
    return {
      fileList: []
    };
  },
  methods: {
    // 提交上传服务器
    async submitUpload() {
      if (!this.fileList || this.fileList.length === 0) return this.$message.warning("请先选择文件");

      const formData = new FormData();
      // key 必须是 'file' 如果后端只支持单文件，这里改为 formData.append('file', this.fileList[0].raw) 即可
      this.fileList.forEach((fileItem) => {
        formData.append("file", fileItem.raw);
      });
      try {
        // 假设后端运行在 3000 端口 api 接口为api/upload
        const res = await axios.post("http://localhost:3000/api/upload", formData);
        if (res.data.code === 200) {
          this.$message.success("上传成功");
          this.fileList = [];
        }
      } catch (err) {
        this.$message.error("上传失败" + err);
      }
    },
    // 文件状态改变时的钩子，添加文件、上传成功和上传失败时都会被调用
    handleChange(_, fileList) {
      this.fileList = fileList;
    },
    // 移除文件时
    handleRemove(_, fileList) {
      this.fileList = fileList;
    },
    // 点击文件列表中已上传的文件时的钩子
    handlePreview(file) {
      console.log("预览文件:", file);
    },
    // 文件数量超限
    handleExceed(files, fileList) {
      this.$message.warning(
        `当前限制选择 3 个文件，本次选择了 ${files.length} 个文件，共选择了 ${files.length + fileList.length} 个文件`
      );
    },
    // 文件上传之前的钩子
    beforeUpload(file) {
      console.log("我是即将被上传的文件：", file.name);
    },
    // 移除之前的钩子
    beforeRemove(file, fileList) {
      return this.$confirm(`确定移除 ${file.name}？共选择了 ${fileList.length} 个文件`);
    }
  }
};
</script>

<style scoped></style>

## 常量颜色

### 统一管理

在多人协作的中大型前端项目中，颜色是最容易失控的一类"细节"。典型痛点：

| 痛点                                                         | 后果                                   |
| ------------------------------------------------------------ | -------------------------------------- |
| 业务代码里直接写死 `#409eff`                                 | 改版换肤时全站搜颜色，漏一处就出"色差" |
| 每个人风格不同（`blue` / `#409EFF` / `rgb(64,158,255)` 表示同一种蓝） | 语义混乱，无法统一替换                 |
| 主色、成功、警告、危险色散落各处                             | 主题无法一键切换（暗色/亮色）          |
| 组件库（Element Plus）颜色与业务色各自一套                   | 两套体系互相打架，视觉不统一           |

**核心目标：**

1. **单一来源**：全站颜色只有一个权威定义位置。
2. **语义化命名**：用 `primary / success / danger` 表达"用途"，而不是 `blue1`。
3. **前后端可访问**：CSS 样式里能用，JS / TS 逻辑里也能用。
4. **可换肤**：改一处，全站生效，甚至支持运行时动态切换主题。

### 主流方案

在 Vue3 + Vite + TS + Element Plus 项目里，大厂一般会在以下三种方案中组合使用：

| 方案                                       | 在哪里定义           | 哪里能用                                  | 优点                                                         | 缺点                           | 适用场景                 |
| ------------------------------------------ | -------------------- | ----------------------------------------- | ------------------------------------------------------------ | ------------------------------ | ------------------------ |
| **① CSS 变量**（`--color-primary`）        | `:root` 全局 CSS     | CSS / Less / SCSS / **JS 都能读**         | 一套变量通吃，原生支持，可运行时换肤，Element Plus 底层就是它 | 老浏览器不兼容（现代项目无碍） | 推荐主方案               |
| **② Less / SCSS 变量**（`@color-primary`） | 全局 `variable.less` | 仅编译期，`<style lang="less">` 内        | 原生预处理器，热更新快，写法简单                             | JS / TS 拿不到                 | 样式内部变量、间距字号等 |
| **③ TS 常量文件**（`COLOR.primary`）       | `constants/color.ts` | 仅 TS / JS（逻辑、echarts、动态内联样式） | 有类型提示，可参与业务逻辑                                   | CSS / Less 里无法直接 import   | 给 JS / TS 逻辑用        |

> 大厂标准做法：
>
> 1. `CSS` 变量（唯一颜色源）+ TS 常量（给逻辑用），两者同一份色值来源，Element Plus 主题色并入这套体系;
>
> 2. `Less / SCSS `变量仅用于"样式内部"的补充变量（间距、字号、圆角），不重复定义颜色，避免双份维护

/* 组件内直接使用，无需再 import */
.appointment-banner {
  background: linear-gradient(135deg, @color-primary, @color-primary-dark);
  color: #fff;
}
```

> ⚠️ **维护原则**：如果两种都用，一定要保证 `variables.less` 与 `variables.css` 色值一致，或干脆**只维护 CSS 变量一份**，Less 变量仅用于间距/字号等非颜色项，避免双份不同步。

#### TS中常量

TS 常量文件 `color.ts`是给 JS / TS 逻辑用；`CSS `变量样式里用，但业务逻辑（动态内联样式、`ECharts` 图表、`Canvas`、接口返回的状态映射）需要的是 `TS` 里的常量。为了保证和 `CSS `变量同源，我们用 `color.ts` 同时导出 `色值常量` 和  `CSS 变量字符串` 两种形态。

##### 基本定义

创建`src/constants/color.ts`并定义如下：

```ts
// src/constants/color.ts
/**
 * 与 src/assets/styles/color-sources/variables.css 保持同一份色值来源
 */

// 1. 纯色值常量（用于 echarts、canvas、动态 style 等 JS 逻辑）
export const COLOR = {
  primary: '#2b85e4',
  primaryLight: '#5ba0eb',
  primaryDark: '#1f63ad',
  success: '#67c23a',
  warning: '#e6a23c',
  danger: '#f56c6c',
  info: '#909399',
  textPrimary: '#303133',
  textRegular: '#606266',
  bgPage: '#f0f2f5',
  medicalReserved: '#2b85e4',
  medicalFull: '#909399',
} as const

// 2. CSS 变量字符串（用于需要写成 var(--xxx) 的场景）
export const CSS_VAR = {
  primary: 'var(--color-primary)',
  success: 'var(--color-success)',
  danger: 'var(--color-danger)',
  bgContainer: 'var(--color-bg-container)',
} as const

// 3. 状态 → 颜色的业务映射（按需扩展，便于后端返回状态码时映射颜色）
export const STATUS_COLOR: Record<string, string> = {
  WAIT: COLOR.warning,      // 待支付
  RESERVED: COLOR.primary,  // 已预约
  COMPLETED: COLOR.success, // 已完成
  CANCELED: COLOR.info,     // 已取消
}
```

| 使用位置                       | 引用方式                          | 示例                                  |
| ------------------------------ | --------------------------------- | ------------------------------------- |
| Vue 组件 `<style>`             | CSS 变量                          | `background: var(--color-primary)`    |

#### 踩坑规范

##### 常见踩坑

1. **❌ 硬编码色值**：业务代码直接写 `#2b85e4`，改版时无从统一。
   - ✅ 一律引用 `var(--xxx)` 或 `COLOR.xxx`。
2. **❌ 双份不同步**：CSS 变量和 Less 变量色值不一致，改了一处漏了另一处。
   - ✅ 尽量**只维护 CSS 变量一份**，Less 仅用于非颜色项。
3. **❌ 非语义命名**：`--blue1`、`--red` 这种按色相命名，含义不明。
   - ✅ 按**用途**命名：`--color-primary`、`--color-danger`、`--color-text-primary`。
4. **❌ 忘记覆盖 Element Plus**：业务和组件两套颜色，视觉打架。
   - ✅ 用 `element-override.css` 把 `--el-*` 指向自己的颜色源。
5. **❌ 全局变量污染**：大量全局变量堆在 `:root`，难维护。
   - ✅ 按**主题色 / 状态色 / 文字 / 边框 / 背景 / 业务扩展**分组注释。

##### 推荐规范

- 命名遵循 `--color-<语义>-<层级>`，如 `--color-text-secondary`。
- 颜色值统一小写十六进制，或统一用变量。
- 提交前用 ESLint 规则拦截硬编码色值（团队内可配置自定义规则）。
- 多套主题时，为每个主题定义独立 `:root.theme-dark` 等作用域，切换类名即可。

#### 主题换肤

若主题为暗色模式，在 `variables.css` 中为暗色主题单独定义一套作用域，只需切换根元素类名。

##### 基本定义

```css
/* 默认亮色主题 */
:root {
  --color-bg-page: #f0f2f5;
  --color-text-primary: #303133;
}

/* 暗色主题：切换 html 上的 .theme-dark 类即生效 */
html.theme-dark {
  --color-bg-page: #141414;
  --color-text-primary: #e5eaf3;
  --color-border: #4c4d4f;
}
```

##### 实际应用

```ts

```

## 模拟接口

### 基础知识

#### 基本定义

Mock.js 拦截浏览器 XMLHttpRequest 请求，前端直接模拟后端接口返回假数据，不需要启动后端服务，前端可以独立开发页面，后端接口完成后直接关掉 mock 即可，业务代码完全不用修改。

#### 核心能力

1. 生成随机模拟数据（姓名、手机号、时间、数组、自增 ID）
2. 拦截 AJAX/axios 请求，匹配 url + 请求方法，返回自定义 JSON

> 注意：Mock.js只在浏览器端生效，node 环境不能拦截 http 请求，打包生产环境必须关闭 mock，不能带到线上。

#### 关键概念

1. mockjs 只匹配 url 路径部分，不关心域名、端口。
2. axios `baseURL: '/prod-api/v2'`，这是前端代理前缀；mock 的正则只写后面路径。
3. 开发环境 vite/webpack devServer 的端口（比如 `localhost:9528`）是 vue 前端服务端口，mock 完全不碰这个端口。
4. 当 mock 匹配成功：直接本地返回模拟数据；匹配失败：才会真的发 http 请求走代理到后端。

#### 安装依赖

```bash
# 开发依赖，只本地用，不要打包进生产
npm install mockjs --save-dev
```

### 核心 API

#### 基本使用

`Mock.mock(rurl, rtype, template|callback)` 

- `rurl`：拦截的接口地址，可以字符串 / 正则
- `rtype`：请求方法，小写 `get/post/put/delete`，必须写，否则拦截全部 method
- `template`：返回的数据模板
- `callback(options)`：回调函数，可以拿到请求参数，模拟后端业务逻辑，`options.body`拿到 post 传参

```js
import Mock from 'mockjs'
// 写法1：直接模板
Mock.mock('/api/user/list','get',{
  code:200,
  msg:'成功',
  'data|10':[{
    'id|+1':1, // id自增
    name:'@cname'
  }]
})

// 写法2：回调函数，可以读取前端传过来参数，做判断（模拟登录校验）
Mock.mock('/api/login','post',(options)=>{
  // post参数在 options.body 是字符串，需要JSON.parse
  const body = JSON.parse(options.body)
  if(body.username === 'admin' && body.password === '123456'){
    return { code:200, data:{token:'admin-token'} }
  }else{
    return { code:400, msg:'账号密码错误' }
  }
})
```

#### 网络延迟

`Mock.setup({timeout:'200‑600'})`,模拟网络延迟，模拟真实接口耗时，单位 ms

```js
Mock.setup({
  timeout:'200‑800' // 请求延迟200~800毫秒随机
})
```

#### 生成数据

`Mock.mock(template)` 只生成随机数据对象，用于 js 代码内直接使用，不拦截网络：

```js
const data = Mock.mock({
  'list|5':[{ id:'@increment', name:'@cname' }]
})
console.log(data)
```

### 数据模板

#### 基本格式

格式：`'属性名|生成规则':初始值`

#### 数组规则

```js
Mock.mock({
  'arr1|5': [1],       // 数组重复5次 [1,1,1,1,1]
  'arr2|3‑8': [{}],    // 数组长度3‑8随机
  'id|+1': 1           // id自增，初始1，每次+1（表格列表必用）
})
```

#### 数字规则

```js
Mock.mock({
  'age|18‑60': 1,          // 18‑60随机整数
  'price|100‑500.1‑2':100  // 整数100‑500，小数1‑2位
})
```

#### 随机占位

随机占位符 `@xxx`（Mock 内置）:

| 占位符              | 作用                           |
| ------------------- | ------------------------------ |
| `@cname`            | 中文姓名                       |
| `@integer(min,max)` | 整数                           |
| `@datetime`         | 日期时间 `2020‑02‑02 12:10:30` |
| `@date`             | 日期 `2025‑08‑08`              |
| `@phone`            | 手机号                         |
| `@email`            | 邮箱                           |
| `@county(true)`     | 省 市 地址                     |
| `@increment`        | 自增数字                       |
| `@guid`             | uuid token 字符串              |
| `@cparagraph(2,4)`  | 中文段落                       |

```js
Mock.mock({
  code:200,
  data:{
    id:'@increment',
    username:'@cname',
    mobile:/^1[3‑9]\d{9}$/, //正则生成手机号
    createTime:'@datetime',
    address:'@county(true)'
  }
})
```

### 注意事项

* 请求方法必须写 `get/post`，小写，不写会拦截全部请求，造成 bug；

* post 请求参数在 `options.body`，是 JSON 字符串，要`JSON.parse(options.body)`；

* 打包生产环境关闭 mock，`VUE_APP_MOCK=false`，mockjs 不能上生产；

* Mock 只能拦截浏览器 axios，不能拦截后端 node 的 axios 请求；

* chrome Network 面板看不到 mock 请求真实 http，请求被 js 拦截，不会真正发出网络包，在 console 打印调试；

* url 匹配优先用正则`/\/api\/customer/`，处理带参数 url，不要写死字符串；

##### 创建目录

在`src/mock`创建后，创建如下几个项目：

###### index.js

```js
import Mock from 'mockjs'
import { ERROR_CODE } from '../base/constants'

// 模拟用户数据库
const mockUserDB = [
  { id:1, username:'admin', password:'123456', nickname:'超级管理员', roles:['admin'] }
]

// 简易内存存储token
let tokenStore = {}

// ------------------- Mock拦截所有请求 -------------------
Mock.setup({
  timeout: 300‑800 // 模拟网络延迟，感受loading
})

// 工具函数：简易校验token，从header取 Authorization: Bearer xxx
function verifyToken(config){
  const auth = config.headers.Authorization
  if(!auth || !auth.startsWith('Bearer ')){
    return { ok:false, code:ERROR_CODE.UNAUTHORIZED, msg:'未登录，请先登录' }
  }
  const token = auth.replace('Bearer ','')
  if(!tokenStore[token]){
    return { ok:false, code:ERROR_CODE.TOKEN_EXPIRED, msg:'登录已过期，请重新登录' }
  }
  return { ok:true, user: tokenStore[token] }
}

// 1、登录接口 post /prod-api/v2/user/login
Mock.mock(/\/prod-api\/v2\/user\/login/, 'post', (options)=>{
  const body = JSON.parse(options.body)
  const {username,password} = body
  const user = mockUserDB.find(u=>u.username === username)
  if(!user){
    return { code:ERROR_CODE.USER_NOT_EXIST, msg:'用户不存在', data:null }
  }
  if(user.password !== password){
    return { code:ERROR_CODE.USER_PASSWORD_ERROR, msg:'密码错误', data:null }
  }
  // 生成模拟token
  const mockToken = 'mock_token_' + Mock.Random.guid()
  tokenStore[mockToken] = user
  return {
    code: ERROR_CODE.SUCCESS,
    msg:'操作成功',
    data:{ token:mockToken }
  }
})

// 2、获取用户信息 get /prod-api/v2/user/info
Mock.mock(/\/prod-api\/v2\/user\/info/, 'get', (options)=>{
  const tokenCheck = verifyToken(options)
  if(!tokenCheck.ok){
    return { code:tokenCheck.code, msg:tokenCheck.msg, data:null }
  }
  const u = tokenCheck.user
  return {
    code:ERROR_CODE.SUCCESS,
    msg:'操作成功',
    data:{ id:u.id, username:u.username, nickname:u.nickname, roles:u.roles }
  }
})

//3、验证码接口 get /prod-api/v2/captcha/captchaImage
Mock.mock(/\/prod-api\/v2\/captcha\/captchaImage/,'get',()=>{
  return {
    code:ERROR_CODE.SUCCESS,
    msg:'操作成功',
    data:{ captchaId:Mock.Random.guid(), image:'data:image/svg+xml;base64,xxxx' }
  }
})

//4、菜单接口 get /prod-api/v2/menu/getRouters
Mock.mock(/\/prod-api\/v2\/menu\/getRouters/,'get',(options)=>{
  const tokenCheck = verifyToken(options)
  if(!tokenCheck.ok){
    return { code:tokenCheck.code, msg:tokenCheck.msg, data:null }
  }
  return {
    code:ERROR_CODE.SUCCESS,
    msg:'操作成功',
    data:[
      { path:'/dashboard', name:'Dashboard', meta:{title:'仪表盘'} },
      { path:'/customer', name:'Customer', meta:{title:'客户管理'} }
    ]
  }
})

export default Mock
```
