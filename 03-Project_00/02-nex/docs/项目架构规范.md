## 一、目录命名规范

### 1.1 通用原则

- 所有目录名使用**全小写字母**
- 多单词使用**连字符（-）**分隔，不使用下划线或驼峰
- 目录名应简洁明了，能够准确表达目录内容
- 避免使用缩写，除非是业界通用缩写（如 `api`、`utils`、`config`）

### 1.2 前端目录命名

| 目录名 | 说明 | 示例 |
|--------|------|------|
| `src/api` | API 接口定义 | ✅ 正确 |
| `src/assets` | 静态资源（图片、图标、样式） | ✅ 正确 |
| `src/components` | 全局通用组件 | ✅ 正确 |
| `src/composables` | 组合式函数 | ✅ 正确 |
| `src/config` | 配置文件 | ✅ 正确 |
| `src/directives` | 自定义指令 | ✅ 正确 |
| `src/filters` | 过滤器 | ✅ 正确 |
| `src/i18n` | 国际化配置 | ✅ 正确 |
| `src/layout` | 布局组件 | ✅ 正确（原 `Layout` 需修改） |
| `src/plugins` | 插件 | ✅ 正确 |
| `src/router` | 路由配置 | ✅ 正确 |
| `src/store` | 状态管理 | ✅ 正确 |
| `src/utils` | 工具函数 | ✅ 正确 |
| `src/views` | 页面组件 | ✅ 正确 |

**禁止示例**：
- ❌ `src/Layout`（大写开头）
- ❌ `src/ProjectConfig`（大写开头）
- ❌ `src/project_config`（使用下划线）

### 1.3 后端目录命名

| 目录名 | 说明 | 示例 |
|--------|------|------|
| `src/config` | 配置文件 | ✅ 正确 |
| `src/constants` | 常量定义 | ✅ 正确 |

| `src/db` | 数据库相关 | ✅ 正确 |

| `src/utils` | 工具函数 | ✅ 正确 |

### 1.4 后端业务模块命名

- 模块目录名使用**全小写字母**
- 多单词使用**连字符（-）**分隔
- 模块名应准确表达业务领域

**正确示例**：
- ✅ `src/modules/user/`
- ✅ `src/modules/i18n-manager/`
- ✅ `src/modules/db-manager/`
- ✅ `src/modules/device-part/`
- ✅ `src/modules/feature-config/`
- ✅ `src/modules/project-config/`

**禁止示例**：
- ❌ `src/modules/i18nManager/`（驼峰命名）
- ❌ `src/modules/db_manager/`（使用下划线）
- ❌ `src/modules/I18nManager/`（大写开头）

## 二、文件命名规范

### 2.1 通用原则

- 文件名应准确表达文件内容和用途
- 文件名使用**小写字母**，多单词使用**连字符（-）**分隔
- 特殊类型文件使用固定后缀（如 `.controller.js`、`.service.js`）
- Vue 组件文件使用 **PascalCase** 或 `index.vue`

### 2.2 前端文件命名

#### 2.2.1 Vue 组件文件

- 全局通用组件：使用 **PascalCase** 命名，放在 `components/组件名/index.vue`
- 页面组件：使用 `index.vue` 命名，放在 `views/模块名/页面名/index.vue`
- 页面专用组件：使用 **PascalCase** 命名，放在页面目录的 `components/` 子目录下

**正确示例**：
- ✅ `components/TranslateProgressDialog/index.vue`
- ✅ `components/SvgIcon/index.vue`
- ✅ `views/super-panel/user/index.vue`
- ✅ `views/super-panel/user/components/UserDialog.vue`

**禁止示例**：
- ❌ `components/translate-progress-dialog/index.vue`（组件目录应使用 PascalCase）
- ❌ `views/super-panel/user/userList.vue`（页面应使用 index.vue）

#### 2.2.2 JS 文件

- 工具函数：使用 **camelCase** 命名
- API 接口：使用 **camelCase** 命名，与后端模块名对应
- 配置文件：使用 **camelCase** 命名，或使用 `.config.js` 后缀
- 状态管理：使用 **camelCase** 命名

**正确示例**：
- ✅ `utils/request.js`
- ✅ `utils/auth.js`
- ✅ `api/user.js`
- ✅ `api/i18n-manager.js`（建议修改，原 `i18nManager.js`）
- ✅ `store/modules/user.js`
- ✅ `config/app.config.js`

**禁止示例**：
- ❌ `utils/Request.js`（大写开头）
- ❌ `api/i18nManager.js`（驼峰命名，应与后端模块名一致使用连字符）

#### 2.2.3 测试文件

- 测试文件使用 `.test.js` 后缀
- 测试文件与被测文件放在同一目录，或放在 `test/` 目录下

**正确示例**：
- ✅ `test/user/user.controller.test.js`
- ✅ `test/user/user.service.test.js`

### 2.3 后端文件命名

#### 2.3.1 模块内文件

后端业务模块内的文件使用**固定后缀**命名，格式为 `模块名.类型.js`：

| 文件类型 | 命名格式 | 示例 |
|---------|---------|------|
| 控制器 | `模块名.controller.js` | `user.controller.js` |
| 服务层 | `模块名.service.js` | `user.service.js` |
| 路由 | `模块名.route.js` | `user.route.js` |
| 数据模型 | `模块名.model.js` | `user.model.js` |
| 数据校验 | `模块名.schema.js` | `user.schema.js` |
| 统一导出 | `index.js` | `index.js` |

**正确示例**（user 模块）：
```
modules/user/
  index.js
  user.controller.js
  user.service.js
  user.route.js
  user.model.js
  user.schema.js
```

**禁止示例**：
- ❌ `modules/user/controller.js`（缺少模块名前缀）
- ❌ `modules/user/UserController.js`（大写开头，缺少固定后缀）
- ❌ `modules/user/userController.js`（驼峰命名，缺少固定后缀）

#### 2.3.2 中间件文件

- 中间件文件使用 `.middleware.js` 后缀
- 文件名使用 **camelCase** 命名

**正确示例**：
- ✅ `middleware/auth.middleware.js`
- ✅ `middleware/error.middleware.js`
- ✅ `middleware/super-admin.middleware.js`（建议修改，原 `superAdmin.middleware.js`）

#### 2.3.3 配置文件

- 配置文件使用 `.config.js` 后缀
- 文件名使用 **camelCase** 或 **连字符** 命名

**正确示例**：
- ✅ `config/app.config.js`
- ✅ `config/db.config.js`
- ✅ `config/jwt.config.js`
- ✅ `config/swagger.config.js`（建议修改，原 `swagger.js`）

**禁止示例**：
- ❌ `config/swagger.js`（缺少 `.config` 后缀）
- ❌ `config/AppConfig.js`（大写开头，缺少固定后缀）

#### 2.3.4 工具函数文件

- 工具函数文件使用 **camelCase** 命名
- 放在 `utils/` 目录下

**正确示例**：
- ✅ `utils/async-handler.js`（建议修改，原 `asyncHandler.js`）
- ✅ `utils/jwt.js`
- ✅ `utils/password.js`

#### 2.3.5 常量文件

- 常量文件使用 **camelCase** 命名
- 放在 `constants/` 目录下

**正确示例**：
- ✅ `constants/error-code.js`（建议修改，原 `errorCode.js`）
- ✅ `constants/status-code.js`（建议修改，原 `statusCode.js`）

### 2.4 静态资源文件命名

#### 2.4.1 图片文件

- 图片文件使用 **全小写字母**，多单词使用**连字符（-）**分隔
- 图片格式使用常见格式（`.png`、`.jpg`、`.svg`、`.webp`）

**正确示例**：
- ✅ `assets/images/user-avatar.png`
- ✅ `assets/images/login-bg.jpg`

#### 2.4.2 SVG 图标文件

- SVG 图标文件使用 **PascalCase** 或 **camelCase** 命名
- 放在 `assets/icons/svg/分类/` 目录下

**正确示例**：
- ✅ `assets/icons/svg/menu/Dashboard.svg`
- ✅ `assets/icons/svg/flags/zh-CN.svg`

### 3.3 后端业务模块标准结构

每个业务模块应包含以下文件（根据需要可选）：

```
modules/模块名/
├── index.js              # 统一导出（必需）
├── 模块名.controller.js   # 控制器（必需）
├── 模块名.service.js      # 服务层（必需）
├── 模块名.route.js        # 路由（必需）
├── 模块名.model.js        # 数据模型（需要数据库操作时）
├── 模块名.schema.js       # 数据校验（需要参数校验时）
└── components/            # 模块专用组件（可选）
    └── ...
```

**模块职责划分**：
- **controller**：处理 HTTP 请求，参数校验，调用 service，返回响应
- **service**：业务逻辑处理，数据库操作，事务管理
- **route**：路由定义，中间件挂载
- **model**：数据库模型定义，数据访问方法
- **schema**：Joi 参数校验规则定义

## 四、命名一致性规范

### 4.1 前后端模块命名对应

前端 API 文件名、前端 views 目录名、后端模块目录名应保持一致：

| 业务领域 | 前端 API | 前端 views | 后端 modules |
|---------|----------|-----------|-------------|
| 用户管理 | `user.js` | `user/` | `user/` |
| 角色管理 | `role.js` | `role/` | `role/` |
| 部门管理 | `dept.js` | `dept/` | `dept/` |
| 字典管理 | `dict.js` | `dict/` | `dict/` |
| 国际化管理 | `i18n-manager.js` | `i18n/` | `i18n-manager/` |
| 数据库管理 | `db-manager.js` | `database/` | `db-manager/` |
| 设备部件 | `device-part.js` | `device/part/` | `device-part/` |
| 功能配置 | `feature-config.js` | `feature/` | `feature-config/` |
| 项目配置 | `project-config.js` | `project-config/` | `project-config/` |

**原则**：
- 后端模块名使用连字符（如 `i18n-manager`）
- 前端 API 文件名与后端模块名一致（如 `i18n-manager.js`）
- 前端 views 目录名可使用简化名（如 `i18n`），但应在文档中说明对应关系

### 4.2 API 路径命名规范

后端 API 路径使用 RESTful 风格：
- 路径使用**全小写字母**，多单词使用**连字符（-）**分隔
- 资源名使用复数形式
- 版本号放在路径前缀（如 `/prod-api/v2/`）

**正确示例**：
- ✅ `GET /prod-api/v2/users`
- ✅ `POST /prod-api/v2/users`
- ✅ `GET /prod-api/v2/users/:id`
- ✅ `PUT /prod-api/v2/users/:id`
- ✅ `DELETE /prod-api/v2/users/:id`
- ✅ `GET /prod-api/v2/i18n-manager/files`
- ✅ `POST /prod-api/v2/i18n-manager/language/create`

## 五、文件存放规范

### 5.1 前端文件存放原则

- **全局通用组件**：放在 `src/components/` 目录下
- **页面专用组件**：放在对应页面目录的 `components/` 子目录下
- **全局工具函数**：放在 `src/utils/` 目录下，按功能分类
- **页面专用工具函数**：放在对应页面目录下
- **全局配置**：放在 `src/config/` 目录下
- **静态资源**：放在 `src/assets/` 目录下，按类型分类
- **API 接口**：放在 `src/api/` 目录下，按业务模块划分

### 5.2 后端文件存放原则

- **业务模块代码**：放在 `src/modules/模块名/` 目录下
- **全局中间件**：放在 `src/middleware/` 目录下
- **全局配置**：放在 `src/config/` 目录下
- **全局工具函数**：放在 `src/utils/` 目录下
- **全局常量**：放在 `src/constants/` 目录下
- **数据库相关**：放在 `src/db/` 目录下
- **控制器基类**：放在 `src/controllers/` 目录下
- **服务基类**：放在 `src/services/` 目录下
- **迁移脚本**：放在 `scripts/migrations/` 目录下
- **测试文件**：放在 `test/` 目录下，按业务模块划分

### 5.3 禁止存放的内容

- ❌ 不要在业务模块目录下存放测试文件（应放在 `test/` 目录下）
- ❌ 不要在业务模块目录下存放迁移脚本（应放在 `scripts/migrations/` 目录下）
- ❌ 不要在业务模块目录下存放临时文件或调试文件
- ❌ 不要在 `utils/` 目录下存放业务逻辑代码（应放在对应模块的 service 中）
- ❌ 不要在 `config/` 目录下存放非配置文件

## 六、导入导出规范

### 6.1 统一导出

- 每个目录应添加 `index.js` 文件，统一导出该目录下的所有文件
- 导入时优先使用目录级别的统一导出，避免写完整路径

**正确示例**：
```javascript
// utils/index.js
export { default as request } from './request/request'
export { default as auth } from './auth/auth'
export { default as permission } from './auth/permission'

// 使用时
import { request, auth } from '@/utils'
```

### 6.2 导入路径规范

- 使用 `@` 别名指向 `src/` 目录
- 避免使用相对路径（如 `../../utils/request`）
- 导入顺序：第三方库 → 全局组件/工具 → 本地组件/工具

**正确示例**：
```javascript
import Vue from 'vue'
import { Message } from 'element-ui'
import { request } from '@/utils'
import { getUserInfo } from '@/api/user'
import UserDialog from './components/UserDialog.vue'
```

### 7.2 命名禁忌

- ❌ 不要使用拼音命名（如 `yonghu.js`、`jiaose.js`）
- ❌ 不要使用无意义的命名（如 `a.js`、`test1.js`、`new.js`）
- ❌ 不要使用中文命名
- ❌ 不要使用特殊字符（如空格、`@`、`#`、`$`）
- ❌ 不要使用保留字（如 `class.js`、`function.js`、`var.js`）
- ❌ 不要在文件名中包含版本号（如 `user-v2.js`，应通过目录或分支管理版本）
