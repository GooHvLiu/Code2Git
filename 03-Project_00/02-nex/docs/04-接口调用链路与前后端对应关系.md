## 一、接口体系总览

### 1.1 路由挂载机制

后端采用**自动扫描路由**机制，启动时遍历 `src/modules/` 目录，自动加载每个模块的 `*.route.js` 文件，并挂载到 `/prod-api/v2/{模块名}` 前缀下。新增模块无需手动注册。

```
前端请求 → http://localhost:3000/prod-api/v2/{module}/{path}
                ↑                    ↑          ↑
         VUE_APP_BASE_API     自动扫描前缀   模块内路由
```

### 1.3 统一响应格式

```json
// 成功响应
{
  "code": 200,
  "msg": "操作成功",
  "data": { ... },
  "timestamp": 1693800000000
}

// 业务错误响应
{
  "code": "ERROR_CODE",
  "msg": "错误描述（中文，调试用）",
  "data": { "field": "xxx", "type": "string.min", "message": "..." },
  "timestamp": 1693800000000
}
```

> 前端根据 `code` 判断业务状态，`data` 中的动态参数用于国际化模板填充。

## 二、核心业务接口链路

### 2.1 登录认证链路

```mermaid
sequenceDiagram
    participant User as 用户
    participant Login as 登录页
    participant Store as Vuex user
    participant API as api/user.js
    participant Req as request.js
    participant BE as 后端 /user

    User->>Login: 输入用户名/密码/验证码
    Login->>Store: dispatch('user/login', form)
    Store->>API: login(form)
    API->>Req: POST /prod-api/v2/user/login
    Req->>Req: 请求拦截器：白名单放行（无需Token），注入lang
    Req->>BE: HTTP POST
    BE->>BE: 校验验证码 → 校验密码 → 生成JWT
    BE-->>Req: { code:200, data:{ token, userInfo } }
    Req->>Req: 响应拦截器：code===200 直接返回
    Req-->>API: Promise resolve
    API-->>Store: 返回 token 和用户信息
    Store->>Store: setToken() 存储到 localStorage
    Store->>Store: setUserInfo() 存储用户信息
    Store-->>Login: resolve
    Login->>Login: $router.push('/') 跳转首页
```

**接口详情**：

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| GET | `/captcha/captchaImage` | 公开 | 获取图形验证码（SVG） |
| POST | `/user/login` | 公开 | 用户登录，返回 Token |
| POST | `/user/register` | 公开 | 用户注册 |
| POST | `/user/forgot-password/send-code` | 公开 | 忘记密码-发送验证码 |
| POST | `/user/forgot-password/reset` | 公开 | 忘记密码-重置密码 |
| GET | `/user/info` | 需认证 | 获取当前登录用户信息 |
| GET | `/user/tokenvalid` | 可选认证 | Token 有效性校验 |

### 2.2 动态路由/菜单加载链路

```mermaid
sequenceDiagram
    participant Router as 路由守卫
    participant Store as Vuex permission
    participant API as api/menu.js
    participant Req as request.js
    participant BE as 后端 /menu

    Router->>Router: beforeEach 全局前置守卫
    Router->>Store: 判断是否已加载动态路由
    alt 未加载
        Store->>API: getRouters()
        API->>Req: GET /prod-api/v2/menu/getRouters
        Req->>Req: 注入 Token + lang
        Req->>BE: HTTP GET（携带 version 缓存头）
        BE->>BE: 校验版本号 → 未变更返回 MENU_NOT_MODIFIED
        BE-->>Req: { code:200, data:{ tree, version } } 或 { code:MENU_NOT_MODIFIED }
        Req-->>API: 返回菜单树
        API-->>Store: 返回菜单数据
        Store->>Store: 生成动态路由（component 懒加载）
        Store->>Store: router.addRoutes() 注册路由
        Store->>Router: next({ ...to, replace:true }) 重进
    else 已加载
        Router->>Router: next() 直接放行
    end
```

**接口详情**：

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| GET | `/menu/version` | 需认证 | 获取菜单最新版本号 |
| GET | `/menu/getRouters` | 需认证 | 获取用户动态路由菜单树（带版本缓存） |

### 2.3 系统配置读写链路


### 2.4 PLC 数据采集与实时推送链路

```mermaid
sequenceDiagram
    participant PLC as PLC设备
    participant Poll as PlcPollTask
    participant Manager as PLC Manager
    participant WS as WebSocket
    participant FE as 前端页面

    Note over Poll,Manager: 后端启动时初始化
    Manager->>PLC: 建立连接（ModbusTcp/OPC UA/S7）
    Poll->>Poll: 启动双频轮询
    loop 快速轮询 200ms
        Poll->>PLC: 读取状态/报警寄存器
        PLC-->>Poll: 返回数据
        Poll->>WS: broadcast plc_data
        WS-->>FE: 实时推送
    end
    loop 慢速轮询 1000ms
        Poll->>PLC: 读取工艺参数寄存器
        PLC-->>Poll: 返回数据
        Poll->>WS: broadcast plc_data
        WS-->>FE: 实时推送
    end

    Note over FE,PLC: 前端主动写入
    FE->>WS: 发送 write_tag 请求
    WS->>Manager: writeTag(tag, value)
    Manager->>PLC: 写入寄存器
    PLC-->>Manager: 写入结果
    Manager->>WS: broadcast plc_write_result
    WS-->>FE: 返回写入结果
    Manager->>Manager: 记录审计日志（GMP合规）
```

**接口详情**：

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| GET | `/plc/status` | 需认证 | 获取 PLC 连接状态 |
| GET | `/plc/read-tag` | 需认证 | 读取单个标签值 |
| GET | `/plc/read-all` | 需认证 | 读取所有标签值 |
| POST | `/plc/write-tag` | 需认证 | 写入标签值（记录审计日志） |

## 四、WebSocket 实时通信链路

### 4.1 WebSocket 消息类型

| 消息类型 | 方向 | 说明 | 触发场景 |
|----------|------|------|----------|
| `plc_status` | 服务端→客户端 | PLC 连接状态变更 | 连接/断开、启动时推送 |
| `plc_data` | 服务端→客户端 | PLC 实时数据 | 轮询采集到新数据 |
| `plc_write_result` | 服务端→客户端 | PLC 写入结果 | 前端请求写入后 |
| `device_status` | 服务端→客户端 | 设备在线状态 | 心跳超时/恢复 |
| `notification` | 服务端→客户端 | 新通知消息 | 系统事件触发通知 |
| `part_life_warning` | 服务端→客户端 | 部件寿命预警 | 寿命达到阈值 |
| `heartbeat` | 双向 | 心跳保活 | 每25秒（可配置） |
| `auth` | 客户端→服务端 | 连接认证 | 连接建立后发送Token |

### 4.2 WebSocket 连接链路

```mermaid
sequenceDiagram
    participant FE as 前端
    participant WS as WebSocket客户端
    participant Server as wsManager
    participant Auth as auth.middleware

    FE->>WS: new WebSocket(ws://host:port)
    WS->>Server: 握手请求
    Server->>Server: 验证连接（查询参数Token）
    alt Token有效
        Server->>Server: 注册连接到用户设备
        Server-->>WS: 连接成功
        WS->>FE: onopen 触发
        loop 每25秒心跳
            Server->>WS: ping
            WS->>Server: pong
            Server->>Server: 更新 last_active_time
        end
    else Token无效
        Server-->>WS: 关闭连接 401
        WS->>FE: onclose 触发，跳登录
    end
```

## 五、错误处理链路

### 5.1 前端错误处理流程

```mermaid
flowchart TD
    A[API 请求] --> B[request.js 响应拦截器]
    B --> C{code === 200?}
    C -->|是| D[返回数据给调用方]
    C -->|否| E{错误码类型}
    E -->|TOKEN_EXPIRED/INVALID| F[顶部警告 + 清除Token + 跳登录页]
    E -->|PERMISSION_DENIED| G[顶部警告：权限不足]
    E -->|PARAM_INVALID| H[按 field.type 查找国际化key<br/>逐级降级：field.type → type → default → 原始消息]
    E -->|MENU_NOT_MODIFIED| I[直接返回，使用缓存菜单]
    E -->|其他业务错误| J[按 code 查找国际化<br/>找不到用 res.msg 兜底]
    E -->|HTTP 403 授权失效| K[顶部警告 + 跳授权导入页]
    E -->|网络错误/5xx| L[自动重试2次（500ms间隔）<br/>失败后提示网络错误]
    F --> M[Promise.reject]
    G --> M
    H --> M
    I --> M
    J --> M
    K --> M
    L --> M
```

### 5.2 后端错误处理流程

```mermaid
flowchart TD
    A[请求进入] --> B[中间件链]
    B --> C{异常?}
    C -->|BusinessError| D[返回业务错误码 + msg + data]
    C -->|ValidationError| E[返回 PARAM_ERROR 码]
    C -->|ER_* 数据库错误| F[返回 DATABASE_ERROR 码<br/>隐藏数据库细节]
    C -->|SyntaxError/TypeError| G[返回 SYSTEM_ERROR 码<br/>记录 stack]
    C -->|未知错误| H[返回 UNKNOWN_ERROR 码<br/>记录 stack]
    D --> I[统一 JSON 响应]
    E --> I
    F --> I
    G --> I
    H --> I
```

## 六、接口设计规范

### 6.1 RESTful 规范

| 操作 | HTTP 方法 | 路径示例 | 说明 |
|------|-----------|----------|------|
| 查询列表 | GET | `/user?page=1&pageSize=20` | 分页查询 |

| 新增 | POST | `/user` | 创建资源 |
| 更新 | PUT | `/user/:id` | 全量更新 |
| 部分更新 | PATCH | `/user/:id/status` | 状态变更等 |
| 删除 | DELETE | `/user/:id` | 删除资源 |
| 批量删除 | DELETE | `/user/batch` | body 传 ID 数组 |

### 6.2 分页参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| page | number | 1 | 当前页码 |
| pageSize | number | 20 | 每页条数（最大100） |
| keyword | string | - | 搜索关键词 |
| sortField | string | - | 排序字段 |
| sortOrder | string | - | 排序方向 asc/desc |

```json
  "code": 200,
  "data": {
    "list": [...],

  }
```
