> 文档版本：v1.0 | 更新日期：2026-09-06 | 适用版本：nexCM-V3 / nexSM-V3

## 一、配置体系总览

项目采用**三层配置体系**，按优先级从高到低：

| 层级 | 存储位置 | 生效方式 | 适用场景 |
|------|----------|----------|----------|
| 环境变量 | `.env` / `.env.development` / `.env.production` | 服务启动时加载，重启生效 | 数据库连接、端口、密钥等敏感/环境相关配置 |
| 配置文件 | `src/config/*.js` | 代码编译时打包，重新构建生效 | 系统常量、UI 参数、网络超时等 |
| 数据库配置 | `nex_system_config` 表 | 运行时读取，修改后立即生效（60秒缓存） | 业务参数、PLC 参数、安全策略等可在线调整的配置 |

## 七、配置访问与修改方式

### 7.1 前端配置访问

```javascript
// 通过统一入口访问所有前端配置
import config from '@/config'

config.REQUEST_TIMEOUT      // 网络配置
config.PAGE_SIZE            // UI 配置
config.MESSAGES.TOKEN_EXPIRED // 文案配置
config.APP_NAME             // 系统配置
```

### 7.2 后端配置访问

```javascript
// 环境变量直接访问
process.env.DB_HOST

// 配置文件访问
const appConfig = require('./config/app.config')

// 数据库配置（通过服务层，带缓存）
const configService = require('./modules/config/config.service')
const allConfigs = await configService.getAllConfigs()       // 获取所有（含缓存）
const value = await configService.getConfigValue('plcHost') // 获取单个
await configService.updateConfigs({ plcHost: '192.168.1.100' }) // 批量更新（清缓存）
```

### 7.3 配置修改生效时间

| 配置类型 | 修改方式 | 生效时间 |
|----------|----------|----------|
| 环境变量 | 修改 .env 文件 | 重启后端服务 |
| 前端配置文件 | 修改 src/config/*.js | 重新构建前端 |
| 数据库系统配置 | 前端「参数配置」页面在线修改 | 立即生效（60秒内缓存自动刷新） |
| 主题变量 | 修改 themeVariables.js | 重新构建前端 |

## 八、配置注意事项

1. **敏感信息**：`.env` 文件包含数据库密码、JWT 密钥、邮箱授权码等敏感信息，**禁止提交到版本控制**，已通过 `.gitignore` 排除。
2. **配置缓存**：数据库系统配置有 60 秒内存缓存，修改后调用 `clearCache()` 可立即生效。
3. **配置类型**：数据库配置值统一以字符串存储，读取时根据 `config_type` 字段自动转换为 number/boolean/json。
4. **新增配置项**：在 `config.model.js` 的 `defaultConfigs` 数组中添加，系统启动时自动补全缺失的配置项（不会覆盖已有值）。
5. **前后端配置一致性**：前端 `network.js` 的 `REQUEST_TIMEOUT` (100000ms) 与后端 `app.config.js` 的 `requestTimeout` 应保持一致。
6. **PLC 配置双轨制**：PLC 连接参数同时存在于环境变量（.env）和数据库配置表中，数据库配置优先级更高（运行时可修改）。
